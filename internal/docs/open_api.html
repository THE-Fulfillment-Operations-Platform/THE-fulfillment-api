Tổng quan

Khi hệ thống của bạn có đơn mới, gọi API này để đơn tự vào xưởng — không cần xuất Excel rồi import. Sau đó bạn hỏi lại API để biết đơn đang ở đâu và lấy mã vận đơn.

Địa chỉ gốchttps://fulfillment.bacgiangdecor.com/api/open/v1
Định dạngJSON, UTF-8. Gửi header Content-Type: application/json.
Xác thựcAPI key do xưởng cấp, gửi trong header.
Thời gianMọi mốc thời gian theo RFC 3339 và có múi giờ. "Ngày" (YYYY-MM-DD) tính theo giờ Việt Nam.
Đặc tả máy đọcopenapi.yaml (OpenAPI 3) — nạp được vào Postman, Insomnia.

Mọi câu trả lời dùng chung một khung:

// Thành công
{ "success": true, "data": { ... } }

// Thất bại
{ "success": false, "error": { "code": "MÃ_LỖI", "message": "Mô tả", "details": [ ... ] } }

Hãy xử lý theo mã HTTP và error.code. Câu chữ trong message có thể thay đổi.

Quy trình kết nối

Các bước từ lúc bắt đầu tới khi đơn thật chạy tự động. Mỗi bước ghi rõ ai làm.

  1. Nhận API keyXưởng Xưởng tạo key cho tài khoản seller của bạn và gửi qua kênh riêng. Key có dạng ffm_…, chỉ xem được một lần lúc tạo — lưu ngay vào nơi cất bí mật của hệ thống bạn (biến môi trường, secret manager), không ghi vào mã nguồn.
  2. Thử keyBạn Gọi GET /ping. Câu trả lời có tên seller của bạn là key đúng.
  3. Đối chiếu mã SKUBạn Lấy danh sách SKU của xưởng bằng GET /skus, rồi lập bảng đổi từ mã sản phẩm bên bạn sang mã SKU của xưởng. API chỉ nhận mã SKU của xưởng.
  4. Gửi đơn thửBạn Gửi 2–3 đơn với order_id bắt đầu bằng TEST-, gồm cả trường hợp nhiều sản phẩm và sản phẩm có file thiết kế. Thử luôn việc gửi lại cùng một đơn để chắc hệ thống bạn xử lý đúng 200 / created: false.
  5. Xưởng kiểm và xác nhậnXưởng Báo xưởng mã các đơn thử. Xưởng kiểm đơn trong hàng chờ duyệt (địa chỉ, SKU, file thiết kế mở được), xác nhận rồi xoá đơn thử.
  6. Chạy thậtBạn Bật gửi đơn thật và bật đồng bộ trạng thái (xem cách làm). Theo dõi kỹ những đơn đầu tiên.

Kiểm tra trước khi chạy thật

  • Key nằm trong biến môi trường / secret manager, không nằm trong mã nguồn hay ứng dụng phía người dùng.
  • Mọi SKU bên bạn đã đổi được sang mã SKU của xưởng.
  • Mỗi đơn có một order_id cố định, không đổi giữa các lần gửi lại.
  • Gặp timeout, lỗi mạng, 429 hoặc 5xx thì tự gửi lại; gặp 422 thì ghi lại error.details để sửa dữ liệu, không gửi lại nguyên xi.
  • Link mockup_url / design_url mở được mà không cần đăng nhập.
  • Có lịch đồng bộ trạng thái và mã vận đơn về hệ thống bạn.

Xác thực

Mỗi request phải mang API key, theo một trong hai cách:

Authorization: Bearer ffm_KEY_CỦA_BẠN
// hoặc
X-API-Key: ffm_KEY_CỦA_BẠN
  • Một key thuộc về đúng một seller. Đơn tạo bằng key nào thuộc seller của key đó — không có trường nào để chọn seller khác.
  • Chỉ gọi API từ máy chủ của bạn. Đừng để key trong ứng dụng di động hay mã chạy trên trình duyệt.
  • Lộ key thì báo xưởng thu hồi và cấp key mới. Key bị thu hồi ngừng hoạt động gần như ngay lập tức.
  • Mỗi hệ thống nên dùng một key riêng, để thu hồi một key không làm gãy hệ thống khác.

GET/ping — kiểm tra key, trả về seller của key:

Gửi lại không sợ trùng đơn

Tạo đơn là idempotent theo order_id. Gửi lại một order_id đã gửi thì API trả về đúng đơn đã tạo, không tạo đơn thứ hai — kể cả khi hai request giống nhau tới cùng lúc.
Mã HTTPdata.createdNghĩa là
201trueVừa tạo đơn mới.
200falseorder_id này đã có. data.order là đơn cũ, không thay đổi gì.

Vì vậy khi gặp timeout, mất mạng, 429 hay 5xx, cứ gửi lại nguyên request (cách nhau vài giây, tăng dần). Cả 200 và 201 đều nghĩa là đơn đã nằm trong hệ thống xưởng.

API không sửa đơn. Gửi lại cùng order_id với nội dung khác thì đơn cũ vẫn giữ nguyên. Cần sửa hoặc huỷ đơn đã gửi, xem Hỏi đáp.

Đồng bộ trạng thái

API chưa tự báo về (chưa có webhook), nên hệ thống của bạn hỏi lại định kỳ. Cách được khuyên dùng:

  1. Cứ 15–30 phút một lần, gọi GET /orders?created_from=<30 ngày trước>&page_size=100 và đi hết các trang (page tới meta.total_pages).
  2. Với mỗi đơn, ghép theo order_id và cập nhật status cùng tracking vào hệ thống bạn.
  3. Đơn đã ở trạng thái cuối (DELIVERED, CANCELLED, REJECTED) thì thôi theo dõi.
  4. Đơn sống lâu hơn 30 ngày mà chưa giao thì tra riêng bằng GET /orders/{order_id}.

Với 120 request/phút mỗi key, cách này đủ cho hàng nghìn đơn mỗi lượt. Code mẫu ở mục dưới có sẵn hàm syncStatuses (Node.js) / sync_statuses (Python, PHP).

Code mẫu

Ba bản dưới đây đã được chạy thử với API: tự gửi lại khi lỗi mạng / 429 / 5xx, in lỗi theo từng trường khi đơn bị từ chối, và có sẵn hàm đồng bộ trạng thái. Key đọc từ biến môi trường FFM_API_KEY.

Node.js 18+ — không cần cài thêm thư viện

Lưu thành ffm.mjs, chạy thử: FFM_API_KEY=ffm_… FFM_TEST_SKU=MÃ-SKU node ffm.mjs

// Node.js 18+ (fetch có sẵn), không cần cài thư viện.
const BASE_URL = process.env.FFM_BASE_URL ?? 'https://fulfillment.bacgiangdecor.com/api/open/v1';
const API_KEY = process.env.FFM_API_KEY; // ffm_... — đọc từ biến môi trường, đừng ghi thẳng vào code

const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

// Gọi API. Tự gửi lại khi mất mạng, timeout, 429 hoặc 5xx — an toàn vì tạo đơn
// không bao giờ tạo trùng cùng order_id. Lỗi 4xx khác thì ném ra ngay.
async function ffm(method, path, body, attempts = 5) {
  for (let i = 1; ; i++) {
    let res;
    try {
      res = await fetch(BASE_URL + path, {
        method,
        headers: { Authorization: `Bearer ${API_KEY}`, 'Content-Type': 'application/json' },
        body: body ? JSON.stringify(body) : undefined,
        signal: AbortSignal.timeout(30_000),
      });
    } catch (err) {
      if (i >= attempts) throw err;
      await sleep(2 ** i * 1000);
      continue;
    }
    if ((res.status === 429 || res.status >= 500) && i < attempts) {
      const retryAfter = Number(res.headers.get('Retry-After'));
      await sleep(retryAfter > 0 ? retryAfter * 1000 : 2 ** i * 1000);
      continue;
    }
    const json = await res.json();
    if (!json.success) {
      const e = new Error(`${res.status} ${json.error.code}: ${json.error.message}`);
      e.status = res.status;
      e.code = json.error.code;
      e.details = json.error.details ?? [];
      throw e;
    }
    return { status: res.status, data: json.data, meta: json.meta };
  }
}

// 1) Gửi một đơn.
export async function sendOrder(order) {
  try {
    const { data } = await ffm('POST', '/orders', order);
    // data.created = false: đơn này đã gửi trước đó — vẫn là thành công.
    console.log(data.created ? 'Đã tạo' : 'Đã có sẵn', data.order.order_id, '→ mã xưởng', data.order.code);
    return data.order;
  } catch (e) {
    if (e.code === 'VALIDATION_ERROR') {
      for (const d of e.details) console.error(`  ${d.field}: ${d.code} — ${d.message}`);
    }
    throw e;
  }
}

// 2) Đồng bộ trạng thái: lấy các đơn tạo từ ngày `since`, từng trang 100 đơn.
export async function syncStatuses(since) {
  for (let page = 1; ; page++) {
    const { data, meta } = await ffm('GET', `/orders?created_from=${since}&page_size=100&page=${page}`);
    for (const o of data) {
      console.log(o.order_id, o.status, o.tracking?.number ?? '');
      // TODO: cập nhật trạng thái / mã vận đơn vào hệ thống của bạn ở đây.
    }
    if (page >= meta.total_pages) break;
  }
}

# Python 3.8+, chỉ dùng thư viện chuẩn.
import json, os, time, urllib.error, urllib.request
from datetime import date, timedelta

BASE_URL = os.environ.get("FFM_BASE_URL", "https://fulfillment.bacgiangdecor.com/api/open/v1")
API_KEY = os.environ["FFM_API_KEY"]  # ffm_... — đọc từ biến môi trường, đừng ghi thẳng vào code


class FFMError(Exception):
    def __init__(self, status, error):
        super().__init__(f"{status} {error['code']}: {error['message']}")
        self.status, self.code, self.details = status, error["code"], error.get("details") or []


def ffm(method, path, body=None, attempts=5):
    """Gọi API. Tự gửi lại khi mất mạng, timeout, 429 hoặc 5xx — an toàn vì tạo
    đơn không bao giờ tạo trùng cùng order_id. Lỗi 4xx khác thì ném FFMError."""
    data = json.dumps(body).encode() if body is not None else None
    for i in range(1, attempts + 1):
        req = urllib.request.Request(BASE_URL + path, data=data, method=method, headers={
            "Authorization": "Bearer " + API_KEY, "Content-Type": "application/json"})
        try:
            with urllib.request.urlopen(req, timeout=30) as res:
                payload = json.load(res)
                return res.status, payload.get("data"), payload.get("meta")
        except urllib.error.HTTPError as e:
            if (e.code == 429 or e.code >= 500) and i < attempts:
                wait = int(e.headers.get("Retry-After") or 0) or 2 ** i
                time.sleep(wait)
                continue
            raise FFMError(e.code, json.load(e)["error"])
        except (urllib.error.URLError, TimeoutError):
            if i == attempts:
                raise
            time.sleep(2 ** i)

$API_KEY = getenv('FFM_API_KEY'); // ffm_... — đọc từ biến môi trường, đừng ghi thẳng vào code

class FFMError extends Exception
{
    public $status;
    public $errorCode;
    public $details;

    public function __construct($status, array $error)
    {
        parent::__construct("$status {$error['code']}: {$error['message']}");
        $this->status = $status;
        $this->errorCode = $error['code'];
        $this->details = isset($error['details']) ? $error['details'] : [];
    }
}

/**
 * Gọi API. Tự gửi lại khi mất mạng, timeout, 429 hoặc 5xx — an toàn vì tạo đơn
 * không bao giờ tạo trùng cùng order_id. Lỗi 4xx khác thì ném FFMError.
 * Trả về [mã HTTP, data, meta].
 */
function ffm($method, $path, $body = null, $attempts = 5)
{
    global $BASE_URL, $API_KEY;
    for ($i = 1; ; $i++) {
        $retryAfter = 0;
        $ch = curl_init($BASE_URL . $path);
        curl_setopt_array($ch, [
            CURLOPT_CUSTOMREQUEST => $method,
            CURLOPT_RETURNTRANSFER => true,
            CURLOPT_TIMEOUT => 30,
            CURLOPT_HTTPHEADER => ['Authorization: Bearer ' . $API_KEY, 'Content-Type: application/json'],
            CURLOPT_HEADERFUNCTION => function ($ch, $line) use (&$retryAfter) {
                if (stripos($line, 'Retry-After:') === 0) {
                    $retryAfter = (int) trim(substr($line, 12));
                }
                return strlen($line);
            },
        ]);
        if ($body !== null) {
            curl_setopt($ch, CURLOPT_POSTFIELDS, json_encode($body, JSON_UNESCAPED_UNICODE));
        }
        $raw = curl_exec($ch);
        $status = curl_getinfo($ch, CURLINFO_RESPONSE_CODE);
        $netError = curl_error($ch);

        $temporary = $raw === false || $status === 429 || $status >= 500;
        if ($temporary && $i < $attempts) {
            sleep($retryAfter > 0 ? $retryAfter : 2 ** $i);
            continue;
        }
        if ($raw === false) {
            throw new RuntimeException('Không gọi được API: ' . $netError);
        }
        $json = json_decode($raw, true);
        if (empty($json['success'])) {
            throw new FFMError($status, $json['error']);
        }
        return [$status, $json['data'], isset($json['meta']) ? $json['meta'] : null];
    }
}

}

Hỏi đáp

Sửa hoặc huỷ đơn đã gửi thế nào?

Bản v1 chưa có API sửa/huỷ. Liên hệ xưởng (hoặc huỷ trên cổng seller nếu bạn có tài khoản). Đừng gửi lại đơn với order_id mới để "sửa" — xưởng sẽ sản xuất cả hai.

Một khách mua nhiều sản phẩm thì gửi mấy đơn?

Một đơn, nhiều dòng trong items. Các dòng cùng đơn được xưởng gom và gửi chung một kiện.

Đơn tôi gửi có được sản xuất ngay không?

Không. Xưởng duyệt trước (PENDING_REVIEW), duyệt xong mới vào sản xuất (IN_PRODUCTION).

Có môi trường thử không?

Chưa có môi trường riêng. Khi thử, đặt order_id bắt đầu bằng TEST- và báo xưởng để xưởng biết đó là đơn thử và xoá đi (xem Quy trình kết nối).

Gửi lại một đơn đã bị xưởng xoá thì sao?

Đơn bị xoá không còn giữ order_id, nên gửi lại sẽ tạo đơn mới. Đơn thử TEST- đã xoá vì vậy gửi lại được bình thường.
